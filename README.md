## 当前版本

**Flash v1.1.1**

v1.1.1 集中修掉了一批"看起来能玩、其实会卡死或被白嫖"的问题：
名字输入在输入流结束时死循环、无限嗑药免费回血、打坐刷等级、死亡原地满血复活，

v1.1.0 集中修复了输入崩溃、精英怪数值错配、存档路径不可靠等问题，并对经验曲线、治疗量和受击减伤做了平衡调整，没有新增玩法系统。

## v1.1.1 改动内容

### 修复的问题

- **名字输入遇到输入流结束会死循环**：`Console.ReadLine()` 返回 null 时仍反复重读，
  现在会提示"输入已结束"并干净退出（v1.1.0 只修了菜单与战斗，漏掉了开场输入名字这一步）。
- **主菜单读不到输入时不会主动结束**：现在显式判断 `null` 并退出，不再多转一圈菜单。
- **菜单里的"治疗"没有任何成本**：可以无限回血，等于绕开了战斗里"每场最多治疗 3 次"的限制。
  现在治疗统一消耗 1 株**草药**，菜单和战斗共用同一套成本。
- **打坐修炼能稳定刷等级**：连续打坐收益递减（40 → 30 → 20 → 10 → 0），
  打一场怪后精力恢复，收益重新从最高开始。
- **死亡只是原地满血复活**：只扣 10% 经验就回满血，惩罚形同虚设。
  现在死亡只恢复 50% 血量，并且强制结束刷怪、回城休整。
- **战斗里的减伤说明和实现对不上**：文档写"最低 35% 减伤"，实现是"伤害至少保留 35%"（最多减伤 65%）。
  现在实现和文档统一为：**减伤 = 5% × 玩家等级，最高 65%**。
- **撤退后还会多提示一次"按任意键进入下一回合"**：现在撤退直接结束本场战斗。
- **打坐获得经验的提示会被清屏吞掉**：现在没升级也会停下来让玩家看清。
- **读档可能把属性和等级搞脱节**：手改的存档会出现"等级 50 但血量还是 100"这种崩坏数值，
  现在读档会以等级推导的数值为下限做校正。
- **存档没有版本号**：以后改存档结构无法识别旧档，现在写入了 `SaveVersion`。
- **存档只能写在程序目录**：程序目录不可写（例如装在 `C:\Program Files`）时会保存失败，
  现在按"程序目录 → 用户数据目录 → 旧版运行目录"的顺序依次尝试。
- **玩家名字没有清洗**：现在会去掉首尾空白、剔除控制字符（例如 ANSI 转义序列）并限制长度。
- **仓库里混进了编译产物和玩家自己的存档**：`bin/`、`obj/`、`saves/` 已加入 `.gitignore` 并移出版本库。

## 自测

仓库里带了一套冒烟测试（`tests/`），改动后跑一下就能确认没有把游戏跑挂：

```bash
bash tests/run_smoke.sh
```

它会用 `tests/smoke/` 下的输入文件依次喂给游戏，检查是否崩溃、是否死循环。
需要 .NET 10 SDK；如果本机是 .NET 9，用 `TARGET_FRAMEWORK=net9.0 bash tests/run_smoke.sh`。
